# Reproducibility Guide

This document fills gaps left by `README.md` and `CLAUDE.md` so that someone
with **no access to the original machine** (`cs29824`) can recreate the
environment, obtain the data, and re-run the experiments / regenerate the
paper's numbers. It does not repeat what `README.md` already documents
(package layout, the metric definitions, the core Python API, or the basic
`uv sync` + `run_scenarios.py` walkthrough) — read that first. `CLAUDE.md`
also documents many `scripts/` commands (paper-macro/citation pipelines,
temperature sweeps, etc.); this file only adds what's missing from both.

**Verification status**: everything below was confirmed by reading
`pyproject.toml`, `uv.lock`, `.gitmodules`, script source/docstrings, and
`git ls-files`, on 2026-07-02. Anything not directly verifiable in the repo
is marked `TODO (Matthew)` rather than guessed.

## 1. Environment — exact recreate steps

```bash
git clone --recurse-submodules https://github.com/AMindToThink/icl-diversity.git
cd icl-diversity
# If you cloned without --recurse-submodules, or the submodule is missing/stale:
git submodule update --init --recursive

uv sync --all-extras
```

- **Python version**: `pyproject.toml` pins `requires-python = ">=3.12"`,
  `.python-version` pins `3.12`, and `uv.lock` (`requires-python = ">=3.12"`,
  resolution markers for 3.12/3.13/3.14) all agree on **3.12+**.
  `README.md`'s "Requires Python ≥ 3.10" is **stale/incorrect** — trust
  `pyproject.toml`/`.python-version` (3.12), not the README, when recreating
  the environment.
- **Submodule**: `.gitmodules` declares one submodule,
  `diversity-eval` → `https://github.com/GuyTevet/diversity-eval.git`
  (currently pinned at commit `c6172997caa04bd8d8c0df12a6faddc2811a726d` on
  its `master` branch — a detached-HEAD checkout, which is expected for
  submodules). This is **not mentioned anywhere in `README.md`**; without
  `git submodule update --init --recursive` the `diversity-eval/` directory
  is empty and every `scripts/*tevet*` / `scripts/compute_tevet_baselines.py`
  / `scripts/compute_icl_metrics_for_tevet.py` script that reads
  `diversity-eval/data/with_metrics/*.csv` will fail.
- **`uv sync --all-extras`** installs the `tinker`, `test`, `dev`, and
  `sampling` (vllm) extras in addition to the base dependencies
  (`torch>=2.0` — `uv.lock` resolves `torch==2.10.0` with CUDA 12 wheels on
  Linux/x86_64 — `transformers`, `accelerate`, `datasets`,
  `sentence-transformers`, `wandb`, `tinker`, etc.). Note `tinker` is a
  **required base dependency** (not just an optional extra) — `uv sync`
  (even without `--all-extras`) will pull it from PyPI
  (`https://pypi.org/simple`, package `tinker==0.16.1`); no private index is
  configured, so plain internet access to PyPI is sufficient to install it,
  but **using** it (see §4) requires a Thinking Machines Tinker account/API
  key.
- Lint/format tooling (`ruff`) is invoked via `uv run ruff check .` /
  `uv run ruff format .` per `CLAUDE.md`; no separate install step needed
  (it's resolved through `uv run`).

## 2. Data — how to obtain every dataset

### 2a. `diversity-eval` submodule data (untracked, third-party)

`diversity-eval/data/` is **not tracked by the submodule's own git** (`git
-C diversity-eval ls-files data` returns 0 files) — confirmed. Per the
submodule's own `README.md` and `utils.py::download_and_place_data()`
(`diversity-eval/utils.py:98-115`), the data is fetched automatically the
first time you run the submodule's own pipeline:

```bash
cd diversity-eval
python run_metrics.py       # or run_experiments.py — both call
                             # utils.download_and_place_data() if data/ is missing
```

which downloads and unzips
`http://diversity-eval.s3-us-west-2.amazonaws.com/data.zip` into
`diversity-eval/data/` (raw + with_metrics + experiments subfolders). You can
also fetch that zip manually and extract it into `diversity-eval/` yourself.

**However**, for reproducing the *icl-diversity paper's* numbers you
typically do **not** need to re-download this submodule data at all: this
repo's own `results/tevet/` directory (216 files, git-tracked) already
contains this project's own precomputed CSVs (per-model, e.g.
`results/tevet/gpt2/...`, `results/tevet/qwen25_completion_v3/...`) that
were generated by feeding `diversity-eval`'s McDiv/conTest/decTest data
through `scripts/compute_icl_metrics_for_tevet.py`. Re-downloading the raw
`diversity-eval/data/` is only needed if you want to regenerate
`results/tevet/**` from scratch (see §3).

### 2b. Hugging Face datasets used directly by this repo's scripts

| Dataset ID | Used by | Purpose |
|---|---|---|
| `tatsu-lab/alpaca_eval` | `scripts/rlhf_experiment/1_download_prompts.py` | 200-prompt subsample (seed=42) of the 805-prompt eval split |
| `yimingzhang/novelty-bench` | `scripts/rlhf_experiment/1_download_prompts.py` | 100-prompt "curated" split, in full |
| `alon-albalak/{model_tag}-noveltybench-responses` (7 repos: `qwen-4b`, `qwen-8b`, `qwen-235b-a22b`, `llama-33-70b`, `gpt-5`, `gpt-5-nano`, `claude-sonnet-4-5`) | `scripts/rlhf_experiment/5b_score_external_nb.py` | External frontier-model responses on the NoveltyBench-curated prompt set, for cross-model comparison |

All are pulled via `huggingface_hub.hf_hub_download` (no `load_dataset` calls
found anywhere in `scripts/`/`src/`/`tests/`), i.e. plain file downloads, no
special dataset-loading script auth beyond normal HF Hub access (these three
repos are ungated as far as could be verified from the code).

### 2c. Everything else (`results/`, `figures/`, `investigations/`)

Nearly all intermediate/raw experiment outputs needed to regenerate the
paper's tables and inline numbers are **git-tracked**, not regenerated data
you need to fetch: `results/mode_count/*.json`, `results/scenario_metrics*.
json` (v2 and v3 variants), `results/tevet/**` (216 files),
`results/rlhf_experiment/**`, `results/tables/*.tex`,
`investigations/cross_mode_surprise_drop/figures/**` (44 files),
`figures/tevet_validation/**` (87 files) are all in git — confirmed via `git
ls-files`. This means `scripts/build_paper_macros.py` (which reads only from
these tracked files) can be re-run to regenerate
`results/tables/paper_macros.tex` **without needing a GPU, model downloads,
or the diversity-eval data** — see §3, tier A.

## 3. Running — entry points and exact commands

Two reproduction tiers, from cheapest to most expensive:

### Tier A — regenerate paper tables/macros/PDF from checked-in results (no GPU, no model downloads)

```bash
uv run python scripts/build_paper_macros.py        # -> results/tables/paper_macros.tex
uv run python scripts/build_bib.py                  # -> paper/refs.bib (needs network: arXiv/Crossref/ACL APIs, no API key)
uv run python scripts/verify_cites.py                # offline lint
uv run pytest tests/test_paper_macros.py tests/test_bib_pipeline.py -v
cd paper && latexmk -pdf main_icml_workshop.tex      # or main_neurips.tex
```

`scripts/build_arxiv.sh` (tracked) packages an arXiv-valid tarball from the
compiled workshop paper (`main_icml_workshop`); see the script header for the
verification steps it runs (page-count check, no undefined refs, no
anonymization leaks).

### Tier B — full pipeline from scratch (GPU + external downloads required)

These reproduce the raw JSON/CSV files that Tier A consumes; **README.md's
"Validation scenarios" section already documents `run_scenarios.py` /
`plot_ak_curves.py` / `test_hypotheses.py`** — note it uses **v2**-named
output files (`scenario_metrics_v2_*`) and `Qwen/Qwen2.5-32B`, whereas the
paper's actual tables/macros (`scripts/build_paper_macros.py`,
`scripts/generate_scenario_table.py`) read **v3**-named files
(`results/scenario_metrics_v3_gpt2_100perm.json`,
`results/scenario_metrics_v3_qwen3b_100perm.json`) built against
`Qwen/Qwen2.5-3B`, e.g.:

```bash
uv run python scripts/run_scenarios.py --n-permutations 100 \
    --output results/scenario_metrics_v3_gpt2_100perm.json
uv run python scripts/run_scenarios.py --base-model Qwen/Qwen2.5-3B --device cuda \
    --n-permutations 100 --output results/scenario_metrics_v3_qwen3b_100perm.json
```

Additional pipelines not documented in `README.md` or `CLAUDE.md`:

- **Mode-count experiment**: `scripts/run_mode_count_experiment.py`
  (docstring has full example: 1000 independent draws per mode count,
  `--base-model gpt2 --device cuda:1 --batch-size 32 --wandb`). Produces
  `results/mode_count/*.json`.
- **Tevet/diversity-eval validation pipeline** (order matters):
  1. `diversity-eval`'s own `run_metrics.py`/`run_experiments.py` (only if
     regenerating `diversity-eval/data/with_metrics/*.csv` from scratch —
     see §2a; otherwise this repo's `results/tevet/` copies suffice).
  2. `uv run python scripts/compute_icl_metrics_for_tevet.py [--base-model ... --device ... --run-tag ...]`
     — enriches Tevet's CSVs with ICL metrics, writes to
     `results/tevet/<run-tag>/`.
  3. `uv run python scripts/compute_tevet_baselines.py` — Tevet's own
     baseline metrics (ρ, OCA).
  4. `uv run python scripts/analyze_tevet_validation.py --run-tag <tag>` and/or
     `uv run python scripts/analyze_c_ainf.py --run-tag qwen25_completion_v3 --skip-fit`
     (also documented in `CLAUDE.md`).
- **RLHF-diversity experiment** (`scripts/rlhf_experiment/`, entirely
  undocumented outside script docstrings), in order:
  1. `uv run python scripts/rlhf_experiment/1_download_prompts.py`
  2. `uv run python scripts/rlhf_experiment/2_sample_responses.py --stage {base,sft,dpo,instruct}`
     (repeat per stage; needs the `sampling` extra / vllm, and hardcodes
     `CUDA_VISIBLE_DEVICES=1` — see §5)
  3. `bash scripts/rlhf_experiment/run_postsample.sh` — waits for any running
     sampler to exit, then runs stage 4 (`3_score_icl_diversity.py`), stage 5
     (`4_score_baselines.py`), stage 5b (`5b_score_external_nb.py`), stage 6
     (`5_analyze_and_figures.py`) in sequence, logging to
     `results/rlhf_experiment/logs/`.
  4. Optional: `3a_truncate_length_matched.py`,
     `6_compare_raw_vs_lenmatched.py`, `5c_cross_model_table.py` for the
     length-matched / cross-model-table variants discussed in the paper.

## 4. External dependencies

- **Hugging Face models** referenced by name in code (real IDs, confirmed by
  `grep`):
  - `gpt2` (default base model, `scripts/run_scenarios.py`, `src/icl_diversity/cli.py`)
  - `Qwen/Qwen2.5-3B`, `Qwen/Qwen2.5-32B` (base models θ)
  - `Qwen/Qwen3-8B-Base`, `Qwen/Qwen3-30B-A3B-Base` (served via Tinker, see below)
  - `meta-llama/Llama-3.1-8B`, `meta-llama/Llama-3.2-1B`, `meta-llama/Llama-3.2-3B`,
    `meta-llama/Llama-3.1-70B` (Tinker cost-estimation defaults / CLI examples;
    Llama repos are gated on HF Hub and require accepting Meta's license +
    an authenticated HF token — this is a general HF Hub requirement, not
    something this repo configures)
  - `allenai/OLMo-2-1124-7B`, `-SFT`, `-DPO`, `-Instruct` (RLHF-diversity
    experiment's 4 policy stages)
  - `sentence-transformers/all-MiniLM-L6-v2` (baseline SentBERT-diversity
    metric, `scripts/rlhf_experiment/4_score_baselines.py`)
- **`diversity-eval` submodule** (GuyTevet/diversity-eval): third-party NLG
  diversity-metric evaluation code + data, see §1/§2a.
- **Weights & Biases (wandb)**: optional, only used when scripts are passed
  `--wandb` (e.g. `run_mode_count_experiment.py`). Project name is hardcoded
  as `"icl-diversity"` (`wandb.init(project="icl-diversity", ...)`,
  `scripts/run_mode_count_experiment.py:271`). Requires `wandb login` or
  `WANDB_API_KEY` set.
- **Tinker (Thinking Machines)**: `src/icl_diversity/tinker_model.py`
  (`TinkerModel`) uses Tinker's `compute_logprobs` endpoint to score
  sequences against remotely-hosted base models (e.g. for
  `Qwen/Qwen3-30B-A3B-Base`, too large to run locally). Requires a Tinker API
  key. `scripts/estimate_tinker_cost.py` and `scripts/compare_tinker_local.py`
  are the relevant driver scripts; live tests in `tests/test_tinker_live.py`
  and `tests/test_parallel_samples.py` auto-skip when `TINKER_API_KEY` is
  unset.
- **Required env vars** (from `.env.example` + code):
  - `TINKER_API_KEY` — required for any Tinker-backed model (`TinkerModel`,
    `--provider` paths that use it). Loaded via `python-dotenv` from a
    repo-root `.env` file, or plain env var.
  - `WANDB_API_KEY` — optional, only if using `--wandb` flags.
  - **`OPENROUTER_API_KEY` / `TOGETHER_API_KEY`** appear in the machine's
    local (untracked) `.env` file but **no source file in this repo currently
    defines or imports code that reads them**, and no `provider="openrouter"`
    string exists in the codebase.
    `git log --follow -- src/icl_diversity/api_model.py` shows the class they
    were for (`APIModel`, providers `together`/`fireworks`) was deliberately
    **replaced by `TinkerModel`** in commit `600ce77` ("Replace APIModel with
    TinkerModel for remote logprob computation"). `scripts/run_mode_count_experiment.py`
    still does `from icl_diversity import APIModel, ...` and offers
    `--provider {local, together, fireworks}` on line ~211-214, but
    `icl_diversity/__init__.py` no longer exports `APIModel` and no
    `src/icl_diversity/api_model.py` file exists — **this import will raise
    `ImportError`** the moment `run_mode_count_experiment.py` is invoked
    (even with `--provider local`, since the import is at module load time).
    `TODO (Matthew): scripts/run_mode_count_experiment.py's --provider
    together/fireworks path (and the top-level "from icl_diversity import
    APIModel" import) appears to be dead code left over from before the

## 5. Hardware

- GPU experiments use NVIDIA CUDA (`uv.lock` resolves `torch==2.10.0` with
  `nvidia-cublas-cu12` etc. for `platform_machine == 'x86_64' and sys_platform
  == 'linux'`).
- A code comment identifies the actual dev GPU used for at least the RLHF
  sampling stage: `scripts/rlhf_experiment/2_sample_responses.py:116` —
  `# Quadro RTX 8000 is compute-capability 7.5 → no bf16 support; use fp16.`
  Quadro RTX 8000 has 48 GB VRAM, consistent with
  `scripts/rlhf_experiment/5c_cross_model_table.py:16` ("Qwen2.5-3B forward
  pass fits within 48 GB VRAM") and `5b_score_external_nb.py:37` ("single 48
  GB card").
- `scripts/rlhf_experiment/2_sample_responses.py`, `3_score_icl_diversity.py`,
  `4_score_baselines.py`, and `5b_score_external_nb.py` all hardcode
  `os.environ.setdefault("CUDA_VISIBLE_DEVICES", "1")` before importing
  torch, described as a repo-wide **"GPU 1 only"** convention on the original
  (multi-GPU, presumably shared) machine. On a different machine — especially
  a single-GPU one — this will silently pin to a nonexistent or wrong device;
  override `CUDA_VISIBLE_DEVICES` explicitly or edit these scripts. `TODO
  (Matthew): confirm whether "GPU 1" was specific to cs29824's device layout
  and document/replace with an explicit --device flag if so.`
- `README.md`'s "GPT-2 on GPU (~2 min with 100 permutations)" / "Qwen2.5-32B
  on multi-GPU (~80 min with 100 permutations)" timings were taken at face
  value (not independently re-verified here) and presumably reflect
  cs29824's hardware; expect different wall-clock time elsewhere.
- No explicit GPU model is named in the paper's LaTeX source itself (checked
  `paper/sections/*.tex` for "GPU"/"A100"/"H100"/"VRAM"/etc. — only a generic
  "we batch them on a single GPU" in `06_practical.tex`).
